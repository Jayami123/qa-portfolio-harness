## D-HAR-C3: a strict guard for the two boolean names

- Context: a passthrough value goes straight into the container, so a typo such as `False` or `yes` would reach the server unchecked.
- Options considered: (a) no guard (as `IS_MULTIWORKSPACE_ENABLED` has today); (b) an exact-match guard for the two new names, run before any file is written.
- Choice: (b). `assertTwentyBooleanPassthrough` accepts only the raw value `true` or `false`. It is called in `writeTwentyRuntimeOverride` before the file is written (`src/adapters/twenty-runtime-override.ts`). `up` calls it at `src/adapters/twenty.adapter.ts:161`, before `composeUp` at `:163`.
- Reason: fail closed, and the error names the variable only. The raw value is checked, not a trimmed copy, because compose interpolates the raw value (so `" true"` would reach the container unchanged). Not applied to `IS_MULTIWORKSPACE_ENABLED`: changing its validation would alter v0.3.1 behaviour, which this PR is not allowed to do. Residual: invalid values for that name still pass through as before.
- Evidence: commit `28a30e7`. Tests: "accept exactly true and false"; `TWENTY_FLAG_INVALID` for `False`, `1`, `maybe` (value not echoed); `" true"` and `"true "` checked by name only (the message contains the word `true`).
