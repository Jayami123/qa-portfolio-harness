## 2 Goal and scope

Completing a document runs the `internal.seal-document` job. That job calls `signPdf()` at the end of `decorateAndSignPdf`. With local signing and `NODE_ENV=production` (Remix `npm run start`), the local transport loads a cert from env or throws `Error: No certificate found for local signing`.

The harness sets `NEXT_PRIVATE_JOBS_PROVIDER=local` and does not set any `NEXT_PRIVATE_SIGNING_*` vars. Seal fails when the job runs, not at health-check time.

**In scope:** point local signing at the fork example `.p12` with an absolute path; fail `up()` before Docker if that file is missing; stop truncating `.harness/documenso-web.log`; unit tests for the path helper and env keys; CHANGELOG, README, `package.json`, and lockfile at 0.2.5.

**Out of scope:** Documenso fork edits; committing a new `.p12` into the harness; generating a cert with OpenSSL; `gcloud-hsm` or `csc` transports; TSA / LTV settings; killing processes; P1 Playwright; merge, tag, or PR.

## 3 Root cause

Seal handler imports `signPdf` from `@documenso/signing`. After fields, certificate, and audit PDF work, `decorateAndSignPdf` calls `await signPdf({ pdf: pdfDoc })`. Earlier failures in the same task (document not complete, unsigned fields, TSP-only paths) are unrelated to the cert.

`NEXT_PRIVATE_SIGNING_TRANSPORT` defaults to `local` when unset (`env('NEXT_PRIVATE_SIGNING_TRANSPORT') || 'local'`). `getSigner()` uses `createLocalSigner()` for `local`. `signPdf()` awaits `getSigner()` then `pdf.sign(...)`.

`loadP12()` in `packages/signing/transports/local.ts`:

1. `NEXT_PRIVATE_SIGNING_LOCAL_FILE_CONTENTS`: base64 `.p12` (checked first).
2. `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH`: filesystem path to `.p12`.
3. If `NODE_ENV !== 'production'`: `./example/cert.p12` relative to process cwd.
4. Else: `throw new Error('No certificate found for local signing')`.

`createLocalSigner()` passes `NEXT_PRIVATE_SIGNING_PASSPHRASE` or `''` to `P12Signer.create`. The bundled example cert is the dev cert with an empty passphrase.

Harness `npm run start -w @documenso/remix` uses `NODE_ENV=production`, so branch 3 never runs. Only an explicit path or contents works. Upstream CI sets `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH: './example/cert.p12'` for the same reason. That relative path is correct only when cwd is `apps/remix`. The harness spawns with `cwd: productRoot`, so a relative path would be wrong. Use an absolute path.

`buildDocumensoAppEnv` today sets DB, SMTP, upload, `NEXT_PRIVATE_JOBS_PROVIDER: "local"`, and webapp URLs. No signing keys. Transport stays `local` (fork `.env` or the app default) with no cert path.

Optional and not set: `NEXT_PRIVATE_SIGNING_REASON`, `NEXT_PUBLIC_SIGNING_CONTACT_INFO`, `NEXT_PRIVATE_USE_LEGACY_SIGNING_SUBFILTER`, `NEXT_PRIVATE_SIGNING_TIMESTAMP_AUTHORITY`. A missing TSA disables LTV and timestamping. It does not block signing.

Error in logs today, after the last signer signs and the seal job runs: `Error: No certificate found for local signing`, stack through `loadP12` → `createLocalSigner` → `getSigner` → `signPdf` → `decorateAndSignPdf` → seal-document handler. A bad path is `ENOENT` from `readFileSync`. A wrong passphrase for a custom cert is a P12/libpdf error, not "No certificate found".

## 4 Design

`documensoLocalSigningCertPath(productRoot)` returns `path.resolve(productRoot, "apps", "remix", "example", "cert.p12")`. Absolute, so Remix cwd does not matter.

`buildDocumensoAppEnv` takes `productRoot` (already on `DocumensoConfig`) and sets:

- `NEXT_PRIVATE_SIGNING_TRANSPORT` = `local`
- `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH` = that absolute path
- `NEXT_PRIVATE_SIGNING_PASSPHRASE` = `""` (bundled cert, same as `.env.example`)

Do not set `NEXT_PRIVATE_SIGNING_LOCAL_FILE_CONTENTS`. Path is enough. Do not set `gcloud-hsm` or `csc`.

`assertDocumensoSigningCert(productRoot, exists = fs.existsSync)` throws when the file is missing. Message includes the absolute path and tells the user to run `npm ci` in the Documenso fork. `exists` is injected so the test stays offline. `up()` calls this immediately after the Node 24 gate and before compose, DNS, migrate, or spawn. The harness does not generate a certificate.

## 5 Unit tests (`src/adapters/documenso-env.test.ts`)

- `documensoLocalSigningCertPath` is absolute and ends at `apps/remix/example/cert.p12` under the given `productRoot`.
- `buildDocumensoAppEnv` sets transport `local`, `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH` to that absolute path, and `NEXT_PRIVATE_SIGNING_PASSPHRASE` to `""`.
- Injected `exists` returning false throws with the path and `npm ci`. Returning true does not throw.

No live Documenso, no OpenSSL, no reading the `.p12` bytes.

## 6 Log append

`startWeb()` calls `fs.writeFileSync(logFile, "")`, which wipes `.harness/documenso-web.log` on every start. `spawnLogged()` already appends `--- spawn <iso> npm run start ... ---` before attaching stdio.

Remove the truncate. Keep `mkdirSync` and the existing "Starting Documenso web" console line. Do not change `spawnLogged`. Seal and job stack traces then remain across restarts.

## 9 Risks

- The example cert is a dev certificate. It is enough for local seal. It is not a production trust chain.
- Empty passphrase matches the bundled cert. A custom cert in the same path with a passphrase would fail inside P12/libpdf, not with "No certificate found".
- Harness env wins over the fork `.env` because dotenv does not override variables already set. A custom `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH` in the fork `.env` will not be used.
- Already-healthy `up()` still checks the cert file before compose. A missing file fails even when port 3001 is already serving. The harness still does not kill that process.
- Log append grows `.harness/documenso-web.log`. That directory is local harness output, not a committed artifact.
