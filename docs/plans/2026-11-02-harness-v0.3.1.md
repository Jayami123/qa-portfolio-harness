## 3. Design per item

### H1 Cal `DATABASE_URL` (no opt-in, a fix)

- Add `DATABASE_URL` to the spawn env in `buildCalApiEnv`. Value is `CAL_DB_URL` (`src/config.ts:35`, default host `localhost`).
- Add a readiness step in `up cal`: one DB-backed read through the API v2 (cheapest candidate is `GET /v2/me` with a lane key, or the `/v2/health` DB probe if the fork exposes one). **Probe to choose this:** P-CAL-1 in section 14 (UNPROBED).
- Compatibility: this is intended for every consumer. Unit test asserts `DATABASE_URL` is present and equals `CAL_DB_URL`.
- Do not print the connection string. The value has a password slot. Log only the host and port.

### H2 Medusa caching (opt-in, two switches)

- Opt-in: `MEDUSA_REDIS=1` (existing) **and** `MEDUSA_FF_CACHING=true` (existing harness pass-through path).
- Register `{ resolve: "@medusajs/medusa/caching", options: { providers: [ { resolve: "@medusajs/medusa/caching-redis", id: "redis", options: { redisUrl: process.env.REDIS_URL } } ] } }` under key `caching`. The exact option shape is UNPROBED until `dist/modules/caching.js` and `caching-redis.js` are read at the pin.
- Keep the existing `cache-redis` entry unchanged for consumers that set neither flag. Decision for owner: whether to remove `cache-redis` when the flag is on (recommended: keep it, see open decision OD-2).
- Compatibility: with `MEDUSA_FF_CACHING` unset, the config output is byte-identical (unit test).

### H3 Inbucket REST export (no opt-in)

- Export `documensoMailApiUrl` as a constant from the harness config (`src/config.ts`). Value `http://127.0.0.1:9003/api/v1/mailbox`, matching `docker/documenso.compose.yml:32`.
- Compatibility: no behavior change.

### H4 Gotenberg for Documenso (opt-in, off by default)

- Opt-in: `DOCUMENSO_GOTENBERG=1`. Off by default, so existing Documenso compose output is unchanged.
- Image: `gotenberg/gotenberg:8@sha256:13672f317b443c793e972b1bd2155ec62a3e7b6891b411e8196442cc053ee5f5` (index digest from PR-006). Pull and runtime behavior are UNPROBED.
- Container name: `qa-harness-documenso-gotenberg`. Publish `127.0.0.1:3010:3000`. Set `NEXT_PRIVATE_DOCUMENT_CONVERSION_URL=http://127.0.0.1:3010` on the Documenso side, passed through the spawn env (never written to the fork `.env`).
- Whether the env var is read at build or at runtime is UNPROBED. If build time, H4 needs a rebuild step and an ADR.
- ADR 0003 is not needed for H4 unless it changes an upstream default. It does not, because the service is off by default (CONTRIBUTING.md:40). Record this decision in the CHANGELOG line.

### H5 Twenty `IS_MULTIWORKSPACE_ENABLED` (opt-in, forwarded only when set)

- Add `"IS_MULTIWORKSPACE_ENABLED"` to `TWENTY_PASSTHROUGH_ENV` (`src/adapters/twenty-passthrough.ts:9-15`). Same behavior as the billing names: blank or whitespace counts as unset.
- Compatibility: a consumer with the variable unset gets byte-identical runtime override output (existing test pattern, `src/adapters/twenty-passthrough.test.ts`).
- STR-002: P-TW-7 says the billing schema is missing on v2.44.0, so H5 may not unblock STR-002. **Verdict: STILL BLOCKED UNTIL PROBED.** Probe P-TW-5/6/7 is UNPROBED.

### H6 Twenty second server replica (opt-in, ADR 0003)

- Opt-in: `TWENTY_SERVER_REPLICAS=2`. Default `1`. Off by default, so the compose output is unchanged.
- Add `server-2` in an overlay file `docker/twenty.replicas.compose.yml`, published `127.0.0.1:<port>`.
- Migration race: the second replica must not run migrations. Set `DISABLE_DB_MIGRATIONS=true` on `server-2` only. **UNPROBED** (P-TW-8).

## 5. ADR 0003 (for H6)

```md
# 0003. Opt-in second Twenty server replica

- Status: Proposed
- Date: 2026-11-03

## Context

`up twenty` runs one server replica. P2 Twenty cache cases (P2-TW-CACHE-001) need two replicas that share one database and one Redis. The compose file in `docker/twenty.compose.yml` is an upstream-shaped overlay, so changing its defaults needs an ADR (CONTRIBUTING.md:40).

## Decision

Add `TWENTY_SERVER_REPLICAS`. Default `1`. When `2`, the harness adds `docker/twenty.replicas.compose.yml`, which starts `server-2` with `DISABLE_DB_MIGRATIONS=true` and a second `127.0.0.1` port. The default compose output does not change.

## Consequences

- A consumer that sets nothing gets the same stack.
- The second replica costs RAM (measured in the live probe, UNPROBED at the time of writing).
- Migration behavior is UNPROBED until P-TW-8 runs.
```

ADR 0004 is not needed. H4 does not change an upstream default because it is off by default.
